### 2026-08-06 — Hand-rolled Outlook-style Calendar component
- `@spine/ui`'s `Calendar` (`packages/ui/src/components/calendar.tsx`): Day/Week/Month/Agenda views, click-drag to create an event, drag-move, drag-resize (Day/Week edges), all-day and multi-day events, side-by-side overlap layout, simple daily/weekly/monthly recurrence (end by date or occurrence count, whole-series edits only, no per-occurrence exceptions), and a fixed 8-color category palette — built from native pointer events (`onPointerDown`/`onPointerMove`/`onPointerUp` + pointer capture), not the HTML5 DnD API and not a wrapped calendar library, per explicit direction. `date-fns` added as `@spine/ui`'s first date-math dependency for week/month boundaries and recurrence-rule arithmetic (DST/month-length correctness delegated to it, never hand-rolled).
- Two pure-logic algorithms in the new `packages/ui/src/lib/calendar-utils.ts`: `expandRecurringEvent`/`expandEventsInRange` (walks a recurrence rule forward from its start date via `date-fns` interval addition, stopping at the count/date end condition or once occurrences pass the visible range, capped at 2000 occurrences against pathological rules) and `layoutOverlappingEvents` (single-pass greedy column assignment — sorted by start then by longer-duration-first, each event takes the lowest free column, and every event in a connected overlap cluster reports the cluster's peak concurrency as its `columnCount` so proportional widths stay consistent across the whole cluster, not just pairwise).
- The pre-existing month-grid `Calendar` (used internally by `DatePicker`) was renamed to `MiniCalendar` and extracted to its own file, `packages/ui/src/components/calendar-mini.tsx`, to free up the `Calendar` export name for the new scheduling component and avoid a self-import; `DatePicker` and the new `Calendar`'s toolbar mini-month-picker both consume it unchanged, per the reuse-don't-rebuild instruction. `MiniCalendarProps` renamed to match.
- New design tokens: an 8-color `category-*`/`category-*-bg` palette (blue/green/amber/red/purple/teal/pink/slate) added to `docs/DESIGN.md` and `packages/config/tailwind-preset.css` for both light and dark mode, deliberately a separate layer from the reserved paid/due-soon/overdue/draft financial-status palette even though some hues are shared — an event's color is a free user label, not a system-derived fact, so Calendar is the only component allowed to read these tokens for categorization.
- Full doc page at `apps/design-system/src/app/components/calendar/page.tsx` on the standard 5-section template (Features/Anatomy/API Reference/Examples/Accessibility), added to `nav.ts` under Data display, with job-site-flavored sample event data (site visits, quote reviews, invoice-due markers, a recurring daily standup and monthly invoicing run) per `docs/spine-prd.md`'s domain.
- Fixed three real bugs found during Playwright-driven interactive verification (not just typecheck/lint): (1) Month view's week rows were all rendering at the same vertical offset instead of stacking — a `grid-rows-[repeat(auto-fill,minmax(0,1fr))]` container without matching `grid-template-columns` doesn't reliably auto-place multi-item rows, replaced with a plain flex column of per-week grid rows; (2) drag-to-create never fired because the empty-slot `onPointerDown` guard (`e.target === e.currentTarget`) was always false — the hour-divider children absorbed every pointer event — fixed by making those dividers `pointer-events-none`; (3) a React 19 "setState while rendering a different component" warning from committing `onSlotCreate`/`onEventUpdate` (which set state on the parent `Calendar`) from inside a `setDrag` state-updater callback in `TimeGrid` — fixed by reading the finished drag from a ref instead of the updater's `prev` argument.
- Verified: `pnpm turbo run typecheck lint --filter=@spine/ui --filter=@spine/design-system` clean; `/components/calendar` returns 200; Playwright screenshots confirmed all four views render without crashing, a 3-way time overlap (Site visit/Team standup/Quote review) lays out side-by-side in Day view, Month view's Aug 6 cell shows 3 events plus a "+1 more" overflow with no row collision, drag-create opens the event editor pre-filled with the dragged range, and drag-move actually changed a sample event's time from 11:00 AM–11:30 AM to 1:15 PM–1:45 PM after drop, with zero console errors on the final pass.
- Stories: extends S-00.1/S-00.6 (component library + docs) — not itself a PRD-numbered story since Calendar isn't yet wired to any domain module (jobs/milestones), but built to the same bar as the rest of `@spine/ui` for whenever a scheduling surface (e.g. a jobs calendar) is needed.

### 2026-08-05 — Auth: Better Auth with per-org roles, cookie sessions, and JWT for mobile
- `apps/api` upgraded to NestJS v11 + Express v5 (from v10) to use the maintained `@thallesp/nestjs-better-auth` integration package — mounts Better Auth's own request handler, registers a global `AuthGuard` (every route requires a session by default; opt out per-route with `@AllowAnonymous()`), and exposes `@Session()`/`@OrgRoles()` decorators.
- Better Auth now owns identity/org/session schema outright (`user`, `session`, `account`, `verification`, `organization`, `member`, `invitation`, `jwks`), generated via its own CLI (`@better-auth/cli generate`) rather than hand-written — replaces the hand-rolled `organisations`/`users`/`memberships`/`sessions` tables from the previous session. All other tables' org/user foreign keys (`accounts`, `journal_entries`, `fiscal_periods`, `number_sequences`, `audit_log`, `settings`) now reference Better Auth's `organization.id`/`user.id` (`text`, Postgres-generated UUIDs — not the app's own `uuid` columns).
- Argon2id password hashing (`@node-rs/argon2`) plugged into Better Auth's `emailAndPassword.password.hash/verify`, replacing its scrypt default, per §10.3.
- Organization plugin configured with three custom roles matching §2.1 exactly — `owner`, `staff`, `field` (not Better Auth's default owner/admin/member) — via `createAccessControl`. Every sign-up automatically becomes the owner of a brand-new organisation (`databaseHooks.user.create.after` calls `auth.api.createOrganization` server-side); there's no self-serve "create another org" or "join an existing org" path in v1, matching the PRD's single-org-per-signup onboarding model.
- JWT plugin issues short-lived (15 min), JWKS-verifiable tokens via `/api/auth/token` for the mobile client, coexisting with cookie sessions for web — exactly the split specified in §5.
- Seed script now signs up a real demo owner (`auth.api.signUpEmail`) rather than inserting an org row directly, so the seeded org is identical in shape to any real signup and exercises the same hook path.
- Verified end-to-end against a live dev DB: sign-up creates the user + org + owner membership; the session cookie authenticates `/api/auth/get-session` and other protected Better Auth endpoints; unauthenticated requests to protected endpoints get a 401; `/api/auth/token` issues a working JWT.

### 2026-08-05 — Postgres + Drizzle: identity/org schema and DB-enforced ledger core
- Drizzle schema for identity & org (`organisations`, `users`, `memberships` with a 4-role enum, `sessions`, `settings`), `number_sequences` (§6.5 gapless numbering), and `audit_log` (§10.4).
- Ledger core (`accounts`, `journal_entries`, `journal_lines`, `fiscal_periods`) per §7 — `journal_lines` carries optional `contact_id`/`job_id` so AR aging and job profitability can be derived from the ledger rather than a parallel calculation, per §7.1.
- The debits-equal-credits invariant (§6.3) is enforced by Postgres itself, not application code: a `DEFERRABLE INITIALLY DEFERRED` constraint trigger validates each entry's balance at COMMIT (a plain `CHECK` doesn't work here — it fires after each single-row line insert, rejecting an entry before its offsetting line lands). Separate triggers make `journal_entries`/`journal_lines` immutable after insert (only `reversed_by_id` may be set once, per the reversing-entry correction model) and reject any UPDATE/DELETE otherwise.
- Chart-of-accounts seed (`apps/api/src/db/seed/`, invoked via `scripts/seed.ts`) matching §14.2 exactly, including which accounts are system-protected (AR, AP, tax, retention, advances, retained earnings).
- Verified directly against Postgres via `docker compose`: balanced entries commit, unbalanced entries are rejected at commit with a clear error, and edits/deletes on committed entries/lines are rejected. Same invariants covered by an automated integration suite (`apps/api/src/db/ledger-integrity.integration.test.ts`, run via `pnpm test:integration`, kept separate from the unit `test` script so CI without a DB still passes).
- `docker-compose.yml`'s `db` service now publishes `127.0.0.1:5432` (loopback-only) so migrations/seed/`db:studio` are reachable from the host without exposing Postgres to the network.
- Stories: S-09.1 (seeded chart of accounts); ledger/numbering/audit schema underpins most of Phase 1+ but isn't itself a numbered story
